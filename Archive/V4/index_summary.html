🪙 Coin Combos — Code Summary

Entry: index.html (45 lines: markup + script tags). Three pages (Coin Combinations, Crystal Garden, Coin Club) switched by S.page. Styles: css/style.css. Logic: seven plain scripts in js/ sharing one global scope, loaded in order core → table → views → strategies → crystals → learn → app. No build step, no dependencies. Companion: schematic.md.

1. Architecture at a glance

User inputdrag coin · edit number · click button
→

Math helpers (ways, sols, minMax, cw) are pure functions of the problem and enabled coin set. Every view and strategy panel is just pXxx() returning an HTML string from the current state.

3. Key ideas

One source of truth
The combo {P,N,D,Q,H,S} drives everything. Table-top coin objects are re-synced to it (syncTable), so editing a number, trading, or dragging all agree.
Solver
sols() recurses from the biggest coin down, pruning when remaining cents can't fit remaining coins (between coins × smallest and coins × next-largest). Capped at 3000 results.
Coin Walk & Rose
Walk: each coin is a step (1 right, up by its value); a solution ends exactly on the target. Rose: six spokes (one per coin); each solution is a polygon whose reach on a spoke is that coin's share of the money or the coins.
Sort animation
Coins position with CSS transform (not an SVG attribute), so adding class anim gives a smooth transition; after 750ms the table re-renders in its final layout.

5. Known limits

  • Touch input and very large sorts are untested.
  • Scripts share globals (no modules); load order in index.html matters.
  • Coins 2–5 tabs are disabled placeholders.
  • Crystal Garden physics and rotation are only checked by eye in a desktop browser; the Spiky prism double-sided change is not yet visually confirmed.
  • The Rose draws at most 400 solutions.
